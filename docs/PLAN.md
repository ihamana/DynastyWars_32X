## P0 結果
### 轉譯正確性
- `tools/x68.py`（code.json 43,402 條 → 補完後 49,491 條指令）。主機驗證 host/xref.c（cpsref＋XLAT）和 Musashi 逐幀比 RAM（略過系統堆疊 0xFF7F00–FF7FFF 與任務槽保存的 CCR 0xFF8007+16k）：cap6 的 4 組輸入（c0_s0、c1_s1、c2_s0、c3_s0）各 400→9000 幀全部一致（參考端 CLK=16MHz）。
- 32X 實機路徑：PicoDrive 跑 t32 測試 ROM，從第一關中途快照（irq 2500）跑 1000 幀，每幀 RAM 雜湊和街機參考一致（0 筆不同）。
- 補上的漏網程式：
  - 跳表 `move.w (d,PC,Dn),Dm ; jmp/jsr (d,PC,Dm.w)`（含負位移、jsr 版）與 `lea (d,PC),An ; move.w (An,Dn.w),Dn ; jsr (An,Dn.w)`：d32 只解出第一筆，x68 重新掃整張表；新入口先「試解碼」，有壞指令或和既有指令重疊就整組不收（discover_safe），最後檢查無重疊。
  - 0x110E–0x11DC 一串 `move.b #n,D0 ; bra $10f0` 小段（extra_seeds.txt）。
- 程式 ROM 是 1MB（0x000000–0x0FFFFF），0x80000 以上是資料表，32X 版要整個放進卡帶並對應頁 0x00–0x0F。

### 轉譯器（x68.py）現況
- A5 固定 0xFFFF8000：`(d,A5)` 直接變常數位址（SH-2 上 0xFF 頁再直接算成 SDRAM 位址）。
- 旗標存活分析：只算後面真的會用到的 N/Z/V/C/X。rts 的後續 = 所有「jsr/bsr 下一條」的需求聯集；trap 不算讀旗標（處理程式自己存 SR，rte 還原）。
- SPLIT 模式（SH-2 用）：
  - 熱區：依主機剖析（tools/hot_c1s1.txt，HOTMIN=1000 次/3500 幀）挑出約 2,053 條指令，合成一個 C 函式，放 SDRAM（92KB），覆蓋約 95% 的執行量；熱區之間互跳都是同函式內 goto。
  - 冷區：其餘依位址切成約 270 個函式，用 -Os、不強制 inline，放卡帶（約 0.88MB）。
  - 分派：先試熱區，不在熱區再用 256 位元組粒度的表找冷區。
- 每幀約 3,480 條 68000 指令（轉譯版，閒置偵測後）；冷區函式呼叫約每幀 18 次。

### SH-2 記憶體配置（測試 ROM，之後沿用）
| SDRAM | 用途 |
|---|---|
| 0x06000000–0FFF | 街機 0xFF0000–0FFF |
| 0x06001000–6FFF | SH-2 程式/資料/堆疊（街機 0xFF1000–6FFF 從未使用） |
| 0x06007000–FFFF | 街機 work RAM 0xFF7000–FFFFFF |
| 0x06010000–1CFFF | 街機 gfx RAM 0x900000–90CFFF |
| 0x06020000–20FFF、28000–28FFF | 街機 0x920000–920FFF、0x928000–928FFF（中間 28KB 空著可用） |
| 0x06029000–3FFFF | 熱區轉譯碼（開機時從卡帶複製） |
- 0x80 I/O 頁：讀取用 512 位元組影子（輸入、DIP、CPS-B ID 0x160=0x0002）；寫入走 io_wb/io_ww（CPS-A/B 暫存器、音效 latch 0x181）。

### 速度（PicoDrive，第一關 1000 幀，WDT 計時）
| 版本 | 平均 | 最慢一幀 |
|---|---|---|
| 單純分段（全部 -O2，放卡帶） | 36% | 66% |
| ＋記憶體存取強制 inline | 32% | 60% |
| ＋熱區合併放 SDRAM、分派改查表 | 22.7% | 47% |
| ＋冷區 -Os（卡帶碼 1.9MB→0.88MB） | 23.1% | 49% |
- 注意：PicoDrive 不模擬 SH-2 快取與卡帶等待，實機可能較慢；熱區放 SDRAM 對實機更重要。

### 測試 ROM（t32/）
- `t32/build.sh` → `DW32xM_P0_SH2test.32x`：畫面顯示驗證結果（幀數、不同筆數）與平均/最慢負載%。
- 卡帶配置：0x0 MD 開機、0x8000 SH-2 SDRAM 程式、0x40000 快照（Cpu 112B＋wram＋gfx）、0x90000 輸入＋雜湊表、0xA0000 熱區碼、0x100000 街機程式 1MB、0x200000 冷區碼。
- 快照產生：xref_split `XLAT=1 CSNAP=<irq> CSNAPF=... INLOG=... XHASH=32 XTRACE=...`。
- sim/sim.c：x86 上用和 SH-2 一樣的頁表/大端存取跑分段碼，找出 1MB 程式 ROM 問題就是靠它。

## P1 v0.1（2026-11-08）：`p1/`（build.sh → DW_32xM_v0.1.32x）
- 開機：主 SH-2 從街機 reset 向量（SSP=RL(0)、PC=RL(4)）開始跑轉譯碼；第一次 cpu_run 跑完街機開機自檢直到閒置。

  - 資料：DW_RE 第一關降色地圖與圖塊（st1bga_tiles 3,721 張、mapA 416x96、mapB 224x96、2 組調色盤）放卡帶 0x3A0000–0x3DF03F，68000 經 1MB bank 視窗（0xA15104=3 → 0x900000）讀。

## v0.4（2026-11-08）：背景前景遮擋
- MD 平面永遠在 32X 畫面後面，所以地圖格有 priority 位元（bit15）的部分（第一關是地圖 A 第 22–23、54–55、86–87 列的草叢帶，共 998 格）由 32X 在角色之後、scroll1 之前再畫一次。
- 只畫「有角色蓋到」的格：主 SH-2 每幀依 sprite 表算 40x28 的 8x8 覆蓋位元圖（sprite_cover），兩顆 CPU 畫自己那一段；開機時先找出哪些地圖列有 priority 格（rowpri）。
- 資料直接讀卡帶上給 MD 用的同一份（0x3A0000 圖塊、0x3C0000 地圖 A），座標用同一個相機（ax=x2+96、ay=272−y2）。
- 顏色：32X CRAM 224–254 固定給 MD 調色盤第 0、1 列（MD 3 位元 → 5 位元），動態配色剩 1–223。
- 驗證：PRIALL 版（全部 priority 格都畫）和 MD 背景完全對齊；草叢會蓋住走到畫面最下面的士兵腳部。
- 代價：最擠的時刻約 −4 幀（36 vs 40）。
- 背景淡入淡出：查過第一關開場，scroll2 調色盤亮度一直是 15（沒有淡入），先不做。

- **修正：接關後背景全黑**（使用者回報：第 2 關死亡後接關，背景消失不再出現）。

  - 修正：render.c 改成只在沒有進行中的遊戲時（ui.c 新增 `ui_playing()`；遊戲中含接關畫面 playing＝1，game over 場景 49 才清掉）才預讀第 1 關。
